## 1. 产品定位与目标

### 1.1 一句话定位

面向法务、商务、投标、招标采购等岗位的 **AI 文档审查助手**：
自动解析合同/标书类文档，识别风险与缺漏，逐条给出可溯源的审查意见与
修改建议，人审复核后形成审查报告。

### 1.2 要解决的核心痛点

| 痛点 | 现状 | 智能体目标 |
|------|------|-----------|
| 审得慢 | 一份合同人工审 1–3 小时 | 分钟级初审，人只做复核 |
| 审得漏 | 依赖个人经验，易漏关键风险条款 | 规则+模型双重覆盖，降低漏审 |
| 标准不统一 | 不同人审查口径不一 | 企业红线条款库统一口径 |
| 投标易废标 | 漏响应招标要求导致废标/丢分 | 逐条响应比对，预警废标项 |
| 经验不沉淀 | 审查经验留在个人脑里 | 案例反哺知识库，越用越准 |

### 1.3 成功指标（北极星 + 辅助）

- 北极星：**单份文档平均审查耗时下降 ≥ 60%**
- 辅助：关键风险点召回率 ≥ 90%；人工采纳率 ≥ 70%；废标项漏报率 ≤ 5%

## 2. 用户与场景

本产品需同时支持四种立场（规则口径随立场切换）：

| 立场/角色 | 典型用户 | 审查侧重 |
|-----------|---------|---------|
| **甲方审合同** | 法务、采购、业务负责人 | 挑风险、护我方利益、责任对等 |
| **乙方做标书/投标** | 投标专员、商务、技术 | 应标完整性、防废标、防丢分 |
| **法务/风控中立把关** | 法务总、风控 | 合规、对照法规与企业红线、一致性 |
| **招标方审投标文件** | 招标采购、评标 | 投标响应符合性、资格符合、横向比对多家 |

### 2.1 立场切换设计

同一份文档，选择不同「审查立场」会加载不同规则集与意见倾向：
- 甲方/乙方：意见倾向保护本方
- 中立把关：仅指出失衡与不合规，不偏向
- 招标方：以招标文件为基准做符合性核验

## 3. 文档类型与分期范围

按价值与复杂度分期落地（四类全要，分期推进）：

### Phase 1（MVP）— 商务合同 + NDA
- 采购/销售/服务合同、框架协议、补充协议
- NDA / 保密协议（结构简单、条款标准化，适合先跑通产品形态）
- 目标：跑通「上传→解析→审查→报告」全链路

### Phase 2 — 招投标文件
- 招标文件、投标文件（技术标 + 商务标）、资格预审
- 核心能力：招标要求逐条响应比对、偏离表生成、废标项预警
- 复杂度最高、价值最高，放在产品形态稳定后做

### Phase 3 — 扩展与深化
- 劳动/租赁等更多合同类型
- 授权书、承诺函、备忘录等
- 多文档关联审查（主合同 + 附件 + 补充协议一致性）

## 4. 功能需求

### 4.1 文档接入与解析（FR-1）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-1.1 | 支持 PDF、Word(docx)、可选 WPS 上传 | P0 |
| FR-1.2 | 扫描件/图片 PDF 走 OCR 转文本 | P1 |
| FR-1.3 | 保留版式结构：章节、条款编号、表格 | P0 |
| FR-1.4 | 识别印章、签名、手写区域（标记位置，不强解析） | P2 |
| FR-1.5 | 解析结果可定位（文本↔原文坐标/页码映射） | P0 |

> 关键约束：**可溯源是底线**。每条审查意见都要能点回原文位置，否则法务不敢采用。

### 4.2 要素抽取（FR-2）

自动抽取结构化关键信息，形成「合同档案卡」：
- 签约主体（甲乙方全称、统一社会信用代码）
- 金额（含大小写一致性校验）、币种、税费
- 期限、生效/终止条件、关键日期节点
- 付款方式与节点、违约责任、争议解决方式
- 招投标场景额外：标的、资质要求、投标有效期、保证金

### 4.3 风险识别与审查（FR-3）

| 编号 | 能力 | 说明 | 优先级 |
|------|------|------|--------|
| FR-3.1 | 缺失条款检查 | 对照标准条款清单，找缺哪些 | P0 |
| FR-3.2 | 单边/失衡条款识别 | 责任、违约、赔偿是否对等 | P0 |
| FR-3.3 | 模糊表述识别 | "尽快""适当"等不确定措辞 | P1 |
| FR-3.4 | 数字/金额一致性 | 前后金额、大小写、合计是否一致 | P0 |
| FR-3.5 | 合规校验 | 对照法规库 + 企业红线条款库 | P0 |
| FR-3.6 | 交叉引用一致性 | "见第 X 条"等引用是否有效 | P1 |
| FR-3.7 | 风险分级 | 每条意见标高/中/低 | P0 |

### 4.4 对比审查（FR-4）

| 编号 | 能力 | 适用场景 | 优先级 |
|------|------|---------|--------|
| FR-4.1 | 与标准模板比对 | 合同偏离标准范本 | P1 |
| FR-4.2 | 招标要求逐条响应比对 | 投标/评标，生成偏离表 | P1（Phase 2）|
| FR-4.3 | 版本 diff | 对方回传修改版，高亮改了什么 | P1 |
| FR-4.4 | 多家投标横向比对 | 招标方评标 | P2（Phase 2）|

### 4.5 审查输出（FR-5）

- 逐条审查意见：**原文引用 + 风险等级 + 问题说明 + 修改建议**
- 可视化批注：在原文上标注（类似 Word 批注）
- 审查报告：可导出 PDF/Word，含风险汇总、分级统计、明细
- 合同档案卡：结构化要素一览

### 4.6 知识库（FR-6）

决定准确率上限，是产品壁垒所在：
- **法规库**：相关法律法规、行业规范
- **企业标准条款库 / 红线库**：可由客户自定义维护
- **历史案例库**：审查结论沉淀，反哺模型与检索
- **标准模板库**：各类合同标准范本

> ✅ 已确认：客户**有存量红线条款与合同模板可导入**，知识库冷启动风险解除。
> 因此 FR-6 需增加「批量导入」能力：
> - FR-6.1 支持批量导入存量条款库（Excel/Word/结构化文件） — P0
> - FR-6.2 支持导入存量合同/标书模板作为比对基准 — P0
> - FR-6.3 导入后做结构化解析、去重、分类入库 — P1

### 4.7 人机协同（FR-7）

- AI 出初审 → 人复核：采纳 / 修改 / 驳回每条意见
- 驳回/修改的反馈回流知识库，持续优化
- 多人协作：分派、批注、评论、状态流转（待审/审中/已审）

### 4.8 审计与权限（FR-8）

- 操作全程留痕（谁、何时、对哪条做了什么）
- 角色权限分级（查看/审查/管理/知识库维护）
- 文档密级管理与访问控制

## 5. 非功能需求（NFR）

| 类别 | 要求 |
|------|------|
| 安全保密 | 加密存储、传输加密；数据合规暂不作为约束（见下方说明） |
| 准确性 | 关键风险召回率 ≥ 90%，宁可多报不可漏报，误报由人过滤 |
| 可溯源 | 100% 意见可定位原文，杜绝模型「幻觉式」结论 |
| 性能 | 单份 50 页文档审查 ≤ 3 分钟（异步可接受） |
| 可解释 | 每条结论给出依据（命中哪条规则/法规/模板） |
| 模型接入 | 统一走 **OpenAI API 格式接口**，模型可替换、不绑定单一厂商 |

> ✅ 已确认：暂不考虑"数据必须留在内网"的合规约束，**部署直接走云端**，
> 不再以私有化作为架构硬约束（大幅简化方案，见第 6 节）。

---

## 6. 部署形态与模型接入（已确认方案）

> 决策：**不考虑数据出内网的合规约束，直接采用云端部署**；
> 模型层统一走 **OpenAI API 格式接口**。私有化不再作为架构硬约束。

### 6.1 部署形态

- **云端 SaaS 单一形态**，无需私有化预留，架构与交付大幅简化
- 文档存储、解析、审查全链路在云端完成
- 仍保留基础安全措施：加密存储 + 传输加密 + 权限/审计

### 6.2 模型接入（OpenAI API 格式）

统一通过 **OpenAI 兼容 API**（`/v1/chat/completions` 等）接入大模型：

| 设计点 | 说明 |
|--------|------|
| 统一接口 | 所有模型调用走 OpenAI API 格式，业务层不感知具体厂商 |
| 模型可配置 | `base_url` + `api_key` + `model` 可配置，便于切换/比价 |
| 兼容性 | OpenAI 官方、以及任何 OpenAI 兼容网关（如各类代理/本地推理服务）均可接入 |
| 关键参数 | 统一管理 temperature、max_tokens、json mode/结构化输出、function calling |
| 容错 | 超时重试、限流退避、失败降级（规则引擎兜底） |

> 好处：审查质量与成本可通过"换模型/换网关"灵活调优，不被单一供应商锁定。
> 后续若需私有化，只要本地推理服务暴露 OpenAI 兼容接口即可平滑切换（天然预留，但不作硬约束）。

## 7. 技术能力依赖（概览，详见后续架构方案）

- 文档解析：版式解析 + 表格抽取 + OCR
- 大模型：抽取、风险研判、意见生成（**统一 OpenAI API 格式接入，模型可替换**）
- 检索增强（RAG）：知识库召回 + 引用溯源（含存量条款/模板导入）
- 规则引擎：硬规则（缺失条款、金额一致性等）与模型互补
- 工作流编排：解析→抽取→规则校验→模型审查→汇总报告

> 注：纯靠大模型不可靠，**「规则引擎 + 大模型 + 知识库检索」三者结合**
> 才能兼顾准确率与可解释性。硬性、确定性的检查交给规则，语义、研判类交给模型。

## 8. MVP 范围界定（Phase 1 验收口径）

**做什么：**
- 商务合同 + NDA 的上传、解析、要素抽取
- 缺失条款、失衡条款、金额一致性、合规红线 4 类核心审查
- 甲方 / 中立两种立场
- 逐条可溯源审查意见 + 可导出审查报告
- 企业红线条款库（可配置）

**不做什么（留给后续）：**
- 招投标逐条响应比对（Phase 2）
- 多家横向比对、多文档关联（Phase 2/3）
- OCR 扫描件（Phase 1 先支持电子版文档）

> 部署：云端单一形态，模型走 OpenAI API 格式接口；存量条款/模板支持批量导入。

## 9. 关键风险与开放问题

| 风险/问题 | 说明 | 状态 |
|-----------|------|------|
| 审查准确率 | 漏审风险点是产品信任的生死线 | ⬜ 需积累测试集做评测 |
| 知识库冷启动 | 红线库/案例库初期为空 | ✅ 已解决：有存量条款/模板可批量导入 |
| 数据合规 | 文档是否须留内网 | ✅ 已确认：不考虑，直接云端部署 |
| 模型选型 | 用哪个具体模型 | ✅ 已定接口（OpenAI API 格式），具体模型可配置/比测 |
| 法规时效 | 法规更新需维护 | ⬜ 法规库更新机制待定 |
| 责任边界 | AI 审查意见的法律责任 | ⬜ 产品定位"辅助"，最终由人负责，需在交互上明确 |
