# 文档审查智能体 — 产品交互设计

> 版本：v0.1
> 日期：2026-06-03
> 配套：PRD.md（v0.2）
> 定位：把「审查能力」落成「用户真正会用、敢用、爱用」的产品体验

---

## 0. 为什么需要这份文档

PRD v0.2 把**审查能力**写清楚了（解析、抽取、风险识别、知识库…），
但**产品形态和交互**是空的。而对审查类工具来说：

> **审查质量决定用户敢不敢用，交互体验决定用户愿不愿意用、用得快不快。**

尤其核心的「原文 ↔ 意见」联动界面，是整个产品的灵魂。本文档专门把它讲透。

---

## 1. 设计原则

1. **可溯源优先**：任何一条意见，一键跳到原文对应位置并高亮。这是信任的基础。
2. **审查即操作**：用户在意见上直接「采纳/驳回/改」，不要让用户在多个界面来回切。
3. **人是决策者，AI 是助手**：AI 给建议，最终采纳与否由人定，交互上要让人「轻松否决」。
4. **进度透明**：异步审查必须有清晰的阶段反馈，不能只有一个转圈。
5. **效率至上**：高频操作（采纳、下一条、导出）都要有快捷键和批量操作。

## 2. 信息架构（IA / 页面地图）

```
登录
└─ 工作台（首页）

   ├─ 报告预览（风险汇总、分级统计、明细）

知识库管理
   ├─ 红线条款库（增删改 + 批量导入）

   ├─ 模型配置（OpenAI 格式接口：base_url/api_key/model）
   ├─ 立场规则配置
   ├─ 成员与权限
   └─ 审计日志
```

## 3. 核心界面详解：审查工作台 ★

这是用户停留时间最长、决定产品成败的界面。采用**双栏联动**布局。

### 3.1 布局线框

```
┌──────────────────────────────────────────────────────────────────────┐
│ 采购合同_v2.docx    立场[甲方▾]   ●高7 ●中12 ●低5   [档案卡][对比][导出]│  ← 顶栏
├────────────────────────────────┬─────────────────────────────────────┤
│                                │  审查意见 (24)   筛选[全部▾][风险▾]   │
│   原  文  渲  染  区             │ ┌─────────────────────────────────┐ │
│                                │ │ ●高  违约责任失衡          [跳转]│ │
│   第三条 付款方式                │ │ 原文："乙方违约赔偿合同总额…"  │ │
│   甲方应于收到发票后…           │ │ 问题：仅约定乙方违约,甲方违约  │ │
│   ▒▒▒▒▒(高亮命中片段)▒▒▒        │ │      无对应责任,权责不对等。  │ │
│                                │ │ 依据：红线#R012 / 合同法对等  │ │
│   第四条 违约责任                │ │ 建议：增加"甲方逾期付款按…"   │ │
│   ▓▓▓▓(选中,黄色高亮)▓▓▓▓       │ │ [✓采纳] [✎改] [✕驳回] [评论]  │ │
│                                │ ├─────────────────────────────────┤ │
│   ...                          │ │ ●高  金额大小写不一致      [跳转]│ │
│                                │ │ ...                            │ │
│                                │ └─────────────────────────────────┘ │
└────────────────────────────────┴─────────────────────────────────────┘
        ↑ 点击右侧"跳转"→左侧滚动定位并高亮对应原文（双向联动）
```

### 3.2 关键交互：双向联动（产品灵魂）

- **意见 → 原文**：点意见卡片 → 左侧自动滚动到对应条款并高亮闪烁。
- **原文 → 意见**：在左侧选中/点击某段文字 → 右侧自动过滤出与该段相关的意见。
- **高亮色彩语义**：红=高风险、橙=中、灰=低；当前选中条款用黄色描边。
- **批注模式**：原文上直接显示批注气泡（可开关），类似 Word/腾讯文档体验。

### 3.3 意见卡片（最小操作单元）

每条意见卡片固定包含五要素，缺一不可：

| 要素 | 作用 |
|------|------|
| 风险等级徽标 | 一眼识别轻重（●高/●中/●低）|
| 原文引用 | 命中的原文片段（可点跳转）|
| 问题说明 | AI 判断的问题是什么 |
| 依据 | 命中哪条红线/法规/模板（**可解释，建立信任**）|
| 修改建议 | 给出可直接用的改法 |

操作按钮：
- **✓ 采纳**：标记采纳，建议进入报告；可「一键插入修改」到文稿（Phase 2）
- **✎ 改**：在 AI 建议基础上人工编辑
- **✕ 驳回**：标记不适用，**驳回理由回流知识库**用于优化
- **评论 / 指派**：协作场景下流转给同事

### 3.4 顶栏

- 风险概览条：●高7 ●中12 ●低5，点击可快速筛选
- 立场切换：切换后**重新加载规则、重跑审查**（给二次确认，避免误触）
- 入口：合同档案卡、对比视图、导出报告

## 4. 其他关键界面

### 4.1 新建审查（向导式，3 步）

降低使用门槛，避免一上来一堆配置项：
```
① 选立场 → ② 选文档类型 → ③ 上传文件 + 选知识库/对比模板 → 开始
```
- 立场和类型用大卡片选择，所见即所得
- 支持拖拽上传、多文件
- 高级选项（指定红线库、对比模板）默认折叠

### 4.2 审查等待态（异步处理）

50 页文档审查需要时间，**不能只给一个转圈**。用阶段式进度：
```
解析文档 ✓  →  抽取要素 ✓  →  规则校验 ◌进行中  →  AI 研判 ○  →  汇总
                                  (已完成的可先看，边出边显示)
```
- 流式输出：审查意见**边生成边出现**在右侧，不用等全部完成
- 失败有明确提示与「重试」，而非卡死

### 4.3 合同档案卡（抽屉/侧栏）

结构化要素一览：签约主体、金额（含大小写校验结果）、期限、付款节点、
关键日期等。每个字段也可点击定位回原文。

### 4.4 对比视图

- **模板比对**：左标准范本、右当前文档，高亮差异
- **版本 diff**：对方回传修改版，高亮改动（增/删/改三色）
- **招标响应表**（Phase 2）：招标要求逐条 × 投标响应，自动标"响应/部分响应/未响应/偏离"

### 4.5 审查报告

- 预览：风险汇总卡片 + 分级饼图 + 意见明细表
- 导出：PDF / Word；可选「含原文批注版」或「纯意见清单版」
- 报告含审查立场、审查人、时间，便于留档

### 4.6 知识库管理

- 红线条款库：列表 + 增删改 + **批量导入**（你已有存量条款，这里是入口）
- 模板库：导入存量合同/标书模板
- 每条红线可配：适用文档类型、立场、风险等级、匹配关键词/语义描述

### 4.7 设置 · 模型配置

落实 PRD 的 OpenAI 格式接口决策：
```
模型服务商：[自定义]
Base URL： https://...../v1
API Key：  ********
模型：     gpt-4o / 其他兼容模型
高级：     temperature、max_tokens、超时与重试
[测试连接]  [保存]
```

## 5. 关键交互细节与状态设计

| 场景 | 设计要点 |
|------|---------|
| 空状态 | 工作台无任务时，引导"新建第一份审查" |
| 加载中 | 阶段式进度 + 流式出意见，不用全局转圈 |
| 零风险 | 明确告知"未发现风险"，而非空白（也要可信地说明审了什么）|
| 误报多 | 提供批量驳回、按类型隐藏，避免淹没用户 |
| 长文档 | 原文区虚拟滚动 + 小地图（minimap）标注风险点位置 |
| 移动端 | MVP 以 Web 桌面端为主（审查是重操作）；移动端只读查看报告 |

---

## 6. 高频操作的效率设计

- 快捷键：`J/K` 上/下一条意见、`A` 采纳、`X` 驳回、`Enter` 跳转原文
- 批量操作：多选意见后批量采纳/驳回/导出
- 自动保存：审查进度实时保存，刷新不丢

## 8. 仍需你拍板的产品问题

1. **首发端**：Web 桌面端优先（推荐），还是要同时考虑客户端/插件（如 Word 插件直接在 Word 里审）？
2. **"一键改稿"深度**：仅给修改建议文本，还是要做到点一下就把建议写回原文档（改稿能力，开发量大但价值高）？
3. **协作强度**：MVP 是否需要多人协作（指派/评论/流转），还是先做单人审查？
4. **报告样式**：是否有客户既定的审查报告模板要套用？

> 建议 MVP：**Web 桌面端 + 单人审查 + 修改建议文本（不自动改稿）+ 标准报告模板**，
> 把核心的「双栏审查工作台」打磨到极致，其余迭代补齐。
