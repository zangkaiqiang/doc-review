# 文档审查智能体 — 产品交互设计

> 版本：v0.2
> 日期：2026-06-03
> 配套：PRD.md（v0.2）
> 定位：把「审查能力」落成「用户真正会用、敢用、爱用」的产品体验
>
> 已确认产品基线：**Web 桌面端优先** · **修改仅给建议文本（不自动改稿）** · **MVP 单人审查**

---

## 0. 为什么需要这份文档

PRD v0.2 把**审查能力**写清楚了（解析、抽取、风险识别、知识库…），
但**产品形态和交互**是空的。而对审查类工具来说：

> **审查质量决定用户敢不敢用，交互体验决定用户愿不愿意用、用得快不快。**

核心的审查工作台是整个产品的灵魂。本文档专门把它讲透。

---

## 1. 设计原则

1. **可溯源优先**：任何一条意见，一键跳到原文对应位置并高亮。这是信任的基础。
2. **审查即操作**：用户在意见上直接「采纳/驳回/改」，不要让用户在多个界面来回切。
3. **人是决策者，AI 是助手**：AI 给建议，最终采纳与否由人定，交互上要让人「轻松否决」。
4. **进度透明**：异步审查必须有清晰的阶段反馈，不能只有一个转圈。
5. **信息密度与聚焦兼顾**：默认让专业用户一屏掌握全局，也能一键进入专注精读。
6. **效率至上**：高频操作（采纳、下一条、导出）都要有快捷键和批量操作。

## 2. 信息架构（IA / 页面地图）

```
登录
└─ 工作台（首页）

   ├─ 立场规则配置
   ├─ 成员与权限
   └─ 审计日志
```

## 3. 核心界面详解：审查工作台 ★

这是用户停留时间最长、决定产品成败的界面。

> ⚠️ 设计修订：早期「左原文 + 右意见列表」的双栏过于简陋——审合同的人需要**一屏
> 掌握全局**（整体风险、条款完整性、要素、每条意见的完整溯源链），而不是一个列表。
> 故升级为 **「顶部仪表盘 + 三栏主区 + 底部停靠区」的多区信息工作台**。
> 双栏保留为「专注模式」可一键切换（见 3.6）。

### 3.2 各区职责（信息密度的来源）

| 区 | 内容 | 解决什么 |
|----|------|---------|
| ① 顶部仪表盘 | 整体**风险评分(0-100)** + 等级 + 风险分级统计(可点筛选) + 立场 + 导出 | 一眼看全局轻重 |
| ② 左栏·导航分析 | **条款完整性进度** + 文档大纲树(每条款带风险标记) + **风险小地图(minimap)** + 多维筛选 | 快速定位、看缺漏、看风险分布 |
| ③ 中栏·原文 | 原文渲染 + 高亮 + 批注气泡 | 阅读与溯源 |
| ④ 右栏·意见工作区 | 上半=**意见列表**(紧凑) + 下半=**选中意见完整详情**(溯源链+操作) | 既能纵览又能深挖单条 |
| ⑤ 底部停靠区 | **合同档案卡 / 条款完整性 / 风险汇总 / 对比** 标签页 | 结构化信息常驻可见，不用反复开抽屉 |

### 3.3 关键交互：三向联动

- **意见 → 原文**：选意见 → 中栏滚动定位并高亮闪烁。
- **原文 → 意见**：点原文某段 → 右栏过滤出相关意见。
- **大纲 / 小地图 → 原文+意见**：点左栏大纲条款或小地图风险块 → 中栏跳转 + 右栏联动。
- **高亮色彩语义**：红=高、橙=中、灰=低；当前选中条款黄色描边。

### 3.4 意见详情（右栏下半部 · 信息最密处）

选中一条意见后，展示**完整溯源链**——这是建立信任、让用户"看到更多信息"的核心：

| 要素 | 说明 |
|------|------|
| 风险等级 + 标题 | ●高 违约责任失衡 |
| 📍原文引用 | 命中片段，点击跳转中栏 |
| ⚠问题说明 | AI 判断的问题 |
| 📖依据（可展开）| 命中的**红线条款编号** + **法规原文**（点⊕展开全文）+ 命中的模板差异 |
| ✏修改建议 | 可直接采用的改法文本（**MVP 仅给建议文本，不自动改稿**）|
| 🕘类似历史案例 | 知识库中相似条款的处理先例（点⊕展开）|
| 操作 | ✓采纳 / ✎改 / ✕驳回（驳回理由回流知识库）|

> 相比旧版列表卡片，新增了**法规原文展开**与**类似历史案例**，让用户不必另开页面
> 就能判断这条意见是否成立——这正是"看到更多信息"的关键。

### 3.5 左栏的三件利器（旧双栏没有的）

1. **条款完整性进度（8/10）**：对照标准条款清单，直观看缺哪两条，点击直达。
2. **文档大纲树**：章节/条款树，每条后带风险标记（●/●●），点击跳转。
3. **风险小地图（minimap）**：整篇文档的缩略风险热力图，红块密集处一眼可见，
   点击即跳——长合同里快速找重点，体验类似代码编辑器的 minimap。

### 3.6 视图模式切换（兼顾"密"与"专注"）

- **完整模式**（默认）：四区全开，信息密度最高，适合通审与决策。
- **专注模式**：折叠左栏与底部区，回到「原文 + 意见」双栏，适合逐条精读。
- 左栏、底部区均可单独折叠；记忆用户偏好。

## 4. 其他关键界面

### 4.1 新建审查（向导式，3 步）

降低使用门槛，避免一上来一堆配置项：
```
① 选立场 → ② 选文档类型 → ③ 上传文件 + 选知识库/对比模板 → 开始
```
- 立场和类型用大卡片选择，所见即所得
- 支持拖拽上传、多文件
- 高级选项（指定红线库、对比模板）默认折叠

### 4.2 审查等待态（异步处理）

50 页文档审查需要时间，**不能只给一个转圈**。用阶段式进度：
```
解析文档 ✓  →  抽取要素 ✓  →  规则校验 ◌进行中  →  AI 研判 ○  →  汇总
                                  (已完成的可先看，边出边显示)
```
- 流式输出：审查意见**边生成边出现**在右栏，不用等全部完成
- 失败有明确提示与「重试」，而非卡死

### 4.3 合同档案卡（底部停靠区常驻标签）

结构化要素一览：签约主体、金额（含大小写校验结果）、期限、付款节点、
关键日期等。每个字段可点击定位回原文。常驻底部，审查全程可见。

### 4.4 对比视图

- **模板比对**：左标准范本、右当前文档，高亮差异
- **版本 diff**：对方回传修改版，高亮改动（增/删/改三色）
- **招标响应表**（Phase 2）：招标要求逐条 × 投标响应，自动标"响应/部分响应/未响应/偏离"

### 4.5 审查报告

- 预览：风险汇总卡片 + 分级饼图 + 意见明细表
- 导出：PDF / Word；可选「含原文批注版」或「纯意见清单版」
- 报告含审查立场、审查人、时间，便于留档

### 4.6 知识库管理

- 红线条款库：列表 + 增删改 + **批量导入**（你已有存量条款，这里是入口）
- 模板库：导入存量合同/标书模板
- 每条红线可配：适用文档类型、立场、风险等级、匹配关键词/语义描述

### 4.7 设置 · 模型配置

落实 PRD 的 OpenAI 格式接口决策：
```
模型服务商：[自定义]
Base URL： https://...../v1
API Key：  ********
模型：     gpt-4o / 其他兼容模型
高级：     temperature、max_tokens、超时与重试
[测试连接]  [保存]
```

## 5. 关键交互细节与状态设计

| 场景 | 设计要点 |
|------|---------|
| 空状态 | 工作台无任务时，引导"新建第一份审查" |
| 加载中 | 阶段式进度 + 流式出意见，不用全局转圈 |
| 零风险 | 明确告知"未发现风险"，而非空白（也要可信地说明审了什么）|
| 误报多 | 提供批量驳回、按类型隐藏，避免淹没用户 |
| 长文档 | 原文区虚拟滚动 + 风险小地图标注风险点位置 |
| 信息过载 | 左栏/底部区可折叠；提供完整/专注两种视图模式 |
| 移动端 | MVP 以 Web 桌面端为主（审查是重操作）；移动端只读查看报告 |

---

## 6. 高频操作的效率设计

- 快捷键：`J/K` 上/下一条意见、`A` 采纳、`X` 驳回、`Enter` 跳转原文、`F` 切换专注模式
- 批量操作：多选意见后批量采纳/驳回/导出
- 自动保存：审查进度实时保存，刷新不丢

## 8. 已确认决策与待办

**已确认：**
- ✅ 首发端：**Web 桌面端优先**（审查是重操作，浏览器内多区工作台）
- ✅ 改稿深度：**仅给修改建议文本**，MVP 不做自动写回原文档
- ✅ 协作：**MVP 先做单人审查**，指派/评论/流转后续迭代
- ✅ 核心界面：从双栏升级为**仪表盘 + 三栏 + 底部停靠区**多区工作台

**待你拍板：**
1. **报告样式**：是否有客户既定的审查报告模板要套用？
2. **风险评分模型**：整体风险评分(0-100)的计算口径需定义（按高/中/低条数加权？）
3. **大纲来源**：左栏大纲树基于文档原有标题，还是按标准条款清单归一化？
